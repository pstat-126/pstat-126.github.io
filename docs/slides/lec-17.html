From Inference to Prediction

Most of this course has focused on inference — understanding the relationship between predictors and the response:

  • Is \(\beta_k\) significantly different from zero?
  • What is a confidence interval for the mean response at \(\mathbf{X}_h\)?
  • Which predictors belong in the model?

Today we shift focus to prediction — how well does our model perform on data it has never seen?

  • Rather than asking “is this predictor significant?” we ask “does adding this predictor make our predictions better?”
  • Rather than measuring fit on the data used to build the model, we estimate performance on new observations

These two goals can lead to different model choices. A predictor can be statistically significant yet not meaningfully improve out-of-sample prediction — and vice versa.

Why Not Just Use \(R^2\)?

The Overfitting Problem

Recall from Lecture 16: \(R^2\) and SSE always improve when we add predictors. They always favor the most complex model.

Consider fitting polynomial models of increasing degree to mtcars:

  • Degree 1: a straight line
  • Degree 5: a wiggly curve
  • Degree 8: an even wigglier curve through the data

Each higher-degree model has lower training SSE and higher \(R^2\). Does that mean it is better?

No. A model that memorizes the training data performs poorly on new, unseen data. This is called overfitting.

Visualizing Overfitting

The line misses the curvature in the data. It underfits by forcing a shape that is too rigid to capture the true relationship.

The curve threads through nearly every point in the training data. It overfits because on new unseen observations it would produce wildly inaccurate predictions wherever the curve swings far from the data.

Training Error vs. Test Error

Training error (MSE on the data used to fit the model) always decreases as model complexity increases.

Test error (MSE on new data the model has never seen) has a U-shape:

  • Too simple \(\rightarrow\) high error from missing real structure (underfitting)
  • Too complex \(\rightarrow\) high error from chasing noise (overfitting)
  • Just right \(\rightarrow\) the sweet spot we are looking for

Key insight: Training MSE is an overly optimistic estimate of how well the model performs on new data. We need a way to estimate test error from our existing data.

The Train/Test Split

The Idea

Solution: Hold out a random subset of observations before fitting. Train on the rest, then evaluate on the held-out data.

Set Purpose Typical size
Training set Fit the model 70–80% of \(n\)
Test set Estimate generalization error 20–30% of \(n\)

Test MSE:

\[\text{Test MSE} = \frac{1}{n_{\text{test}}} \sum_{i \in \text{test}} (Y_i - \hat{Y}_i)^2\]

where \(\hat{Y}_i\) comes from the model fit on the training set only.

Train/Test Split in R

set.seed(126)
train_idx  <- sample(1:n, size = floor(0.75 * n))
train_data <- mtcars[train_idx, ]
test_data  <- mtcars[-train_idx, ]

fit_train  <- lm(mpg ~ wt + qsec + am, data = train_data)
test_preds <- predict(fit_train, newdata = test_data)

test_mse <- mean((test_data$mpg - test_preds)^2)
round(test_mse, 3)
[1] 8.363

Limitation of a Single Split

The test MSE depends heavily on which observations happened to end up in the test set.

seeds <- c(1, 42, 99, 200, 500)
mses  <- sapply(seeds, function(s) {
  set.seed(s)
  idx <- sample(1:n, size = floor(0.75 * n))
  fit <- lm(mpg ~ wt + qsec + am, data = mtcars[idx, ])
  mean((mtcars[-idx, "mpg"] - predict(fit, mtcars[-idx, ]))^2)
})
round(mses, 2)
[1]  8.66 10.66  7.75  5.09 10.07

The estimates vary widely across splits. A single train/test split gives a high-variance estimate of test error. We need something more stable.

These 5 values are the test MSE from each of 5 different random 75/25 splits. Same model, same data, just different observations in the test set each time.

\(k\)-Fold Cross-Validation

The Idea

Instead of one split, partition all \(n\) observations into \(k\) equal-sized folds.

Algorithm: For \(j = 1, 2, \ldots, k\):

  1. Hold out fold \(j\) as the validation set
  2. Fit the model on the remaining \(k - 1\) folds
  3. Compute MSE on the held-out fold \(j\): \(\;\text{MSE}_j = \frac{1}{|j|}\displaystyle\sum_{i \in \text{fold }j}(Y_i - \hat{Y}_i)^2\)

Average across all folds:

\[\text{CV}_{(k)} = \frac{1}{k}\sum_{j=1}^{k} \text{MSE}_j\]

Every observation is used for both training and validation exactly once. The result is a much more stable estimate of test error.

Choosing \(k\)

\(k\) Name Bias Variance Cost
\(n\) LOOCV Low High Expensive (\(n\) model fits)
5 or 10 \(k\)-fold Moderate Low Cheap (5 or 10 fits)

Rule of thumb: \(k = 5\) or \(k = 10\) is the standard choice. They give a good bias–variance tradeoff and are computationally inexpensive.

LOOCV (leave-one-out CV): each fold is a single observation. The model trains on \(n - 1\) observations and evaluates on the one left out. Unbiased but high-variance, and slow for large \(n\).

10-Fold CV in R — Manual Implementation

set.seed(126)
k     <- 10
folds <- sample(rep(1:k, length.out = n))

cv_mse <- numeric(k)
for (j in 1:k) {
  train_j <- mtcars[folds != j, ]
  val_j   <- mtcars[folds == j, ]
  fit_j   <- lm(mpg ~ wt + qsec + am, data = train_j)
  cv_mse[j] <- mean((val_j$mpg - predict(fit_j, val_j))^2)
}

round(cv_mse, 2)         # MSE for each fold
 [1]  9.84  4.97  4.53 13.59 10.96  1.48  0.39 10.83  5.01  6.14
round(mean(cv_mse), 3)   # CV(10) estimate
[1] 6.773

Cross-Validation for Model Selection

Comparing Candidate Models

CV gives a principled way to compare models: the model with the lowest CV MSE is preferred because it has the best estimated out-of-sample predictive accuracy.

Let’s compare three models from Lecture 16:

Model Formula
\(M_1\) mpg ~ wt
\(M_2\) mpg ~ wt + hp
\(M_3\) (backward selected) mpg ~ wt + qsec + am

We will write a small helper function and compute 10-fold CV MSE for each model.

CV MSE Comparison — Code

set.seed(126)
folds <- sample(rep(1:10, length.out = n))

cv_for <- function(formula, data, folds) {
  mse_j <- numeric(max(folds))
  for (j in seq_along(mse_j)) {
    fit   <- lm(formula, data = data[folds != j, ])
    val   <- data[folds == j, ]
    mse_j[j] <- mean((val$mpg - predict(fit, val))^2)
  }
  mean(mse_j)
}

results <- data.frame(
  Model  = c("wt", "wt + hp", "wt + qsec + am"),
  CV_MSE = round(c(
    cv_for(mpg ~ wt,             mtcars, folds),
    cv_for(mpg ~ wt + hp,        mtcars, folds),
    cv_for(mpg ~ wt + qsec + am, mtcars, folds)
  ), 3)
)
results
           Model CV_MSE
1             wt  9.705
2        wt + hp  7.209
3 wt + qsec + am  6.773

Interpreting the Results

           Model CV_MSE
1             wt  9.705
2        wt + hp  7.209
3 wt + qsec + am  6.773
  • mpg ~ wt has the highest CV MSE .wt alone leaves a lot of variation unexplained
  • mpg ~ wt + qsec + am (the backward-selected model from Lec 16) has the lowest CV MSE. It generalizes best to new data

Cross-validation and AIC/BIC agree here: the model chosen by backward stepwise in Lecture 16 also wins under CV. When both methods point to the same model, it builds confidence in that choice.

CV vs. AIC/BIC

Both CV and AIC/BIC estimate out-of-sample predictive accuracy. How do they differ?

AIC / BIC \(k\)-Fold CV
Measures Penalized log-likelihood Direct estimate of test MSE
Requires Distributional assumptions (\(\epsilon \sim N\)) Only predictions
Speed Fast — one fit per model Slower — \(k\) fits per model
Result Dimensionless score (lower = better) MSE units (interpretable)

For standard regression, AIC and 10-fold CV tend to select the same model. When they disagree, CV is often preferred for predictive tasks because it makes no distributional assumptions and reports error in the original units of \(Y\).

Summary

  • Overfitting: Training MSE always decreases as models grow more complex; it is an overly optimistic measure of generalization. A high-degree polynomial fits the training data well but fails on new data

  • Train/test split: Randomly hold out 20–30% of observations before fitting; compute test MSE on the held-out set; valid but high-variance — the estimate changes with the random split

  • \(k\)-fold CV: Partition data into \(k\) folds; for each fold, train on the remaining \(k-1\) folds and evaluate on the held-out fold; average the \(k\) MSEs to obtain \(\text{CV}_{(k)}\); \(k = 5\) or \(k = 10\) is the standard choice

  • LOOCV: Special case \(k = n\); unbiased but high-variance and expensive

  • Model selection via CV: Compare CV MSE across candidate models; the model with the lowest CV MSE is preferred for out-of-sample prediction

  • CV vs. AIC/BIC: Both estimate test error; AIC/BIC are fast and model-based; CV is slower but assumption-free and reports error in interpretable MSE units; both methods typically agree for standard regression
